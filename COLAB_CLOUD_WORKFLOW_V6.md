# Google Colab Workflow — Train, Test, and Export Voice Ubuntu NLP v6

This workflow keeps model training, testing, and final ZIP creation in Colab. The final package is written directly to Google Drive; it does not need to be downloaded from Colab to your computer.

## One-time preparation

1. In Google Drive, create or open `My Drive/VoiceUbuntuNLP/`.
2. Place `Voice_Ubuntu_NLP_v6_SOURCE.zip` in that folder. It contains the expanded data, model source, evaluation data, tests, and Colab notebook.
3. Open `Voice_Ubuntu_NLP_v6_Colab_Train_Test_Export.ipynb` in Colab. If opening it via **File > Upload notebook**, import the notebook once. The source ZIP must be present in Drive as named above.

## Run all stages

Choose **Runtime > Run all**. Authorize Google Drive when prompted.

The notebook will:

1. Extract the v6 source ZIP into Colab's temporary runtime.
2. Install required Python dependencies.
3. Rebuild the expanded training dataset from `training_examples_v5_original.csv`.
4. Train a new Logistic Regression + TF-IDF model from the expanded dataset.
5. Run all pytest tests.
6. Run the held-out evaluation file and parser/entity smoke tests.
7. Verify key model/code/report files and archive integrity.
8. Write `Voice_Ubuntu_NLP_v6_TESTED.zip` directly to `My Drive/VoiceUbuntuNLP/`.

The separate reports are saved in the package and in the project folder generated by Colab.

## Expected result

The current prepared v6 project has 1,348 training phrases across 15 intents, including the new `PLAY_MEDIA` intent. The current development checks show 36 automated tests passing, with 40/40 manually curated independent text examples correct and no exact normalized phrase overlap with the training CSV. These figures are specific to the current authored dataset and do not guarantee real-world speech accuracy.

## If the notebook stops

- If it cannot find the ZIP, check its name and Drive path.
- If dependency installation fails, read the cell's installation error before continuing.
- If any test fails, the export step should not be treated as successful. Review `FINAL_VALIDATION_REPORT_V6.txt` and `final_validation_v6.json`.
- Do not interpret random holdout accuracy as a production benchmark; template-generated variants can make the random split optimistic.

## Integration caution

The NLP model only outputs intent/entities/status. It does not operate Ubuntu. Person 6 must validate and authorize each action, and Person 5 must execute only approved structured operations. Full microphone/STT/GUI/security/Linux integration still requires tests on the actual Ubuntu environment.
